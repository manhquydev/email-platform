# Support Ticket API Incident Diagnosis

## Executive Summary
The reported issue where `POST /support/tickets` returns 405 and `GET` returns HTML is **not reproducible** on the API endpoint (`api.manhquy.click`). The API is functioning correctly. The symptoms strongly indicate that the client is incorrectly sending requests to the **Frontend URL** (`app.manhquy.click`) instead of the **API URL**.

## Investigation Findings

### 1. Route Verification
- **Status**: Verified
- **Details**:
  - `services/api/src/server.ts` correctly imports and registers `supportRoutes`.
  - `services/api/src/routes/support.ts` correctly defines `POST /support/tickets` and `GET /support/tickets`.
  - Registration is done without a prefix override, preserving the `/support/tickets` path.

### 2. Live API Testing
Direct tests against `https://api.manhquy.click/support/tickets` yielded expected API responses, contradicting the reported failure mode:

| Method | Expected | Actual | Status |
|--------|----------|--------|--------|
| `POST` | 400/201 | **400 Bad Request** | ✅ Works (JSON error: "Body cannot be empty") |
| `GET`  | 401/200 | **401 Unauthorized** | ✅ Works (JSON error: "Unauthorized") |
| `OPTIONS` | 204 | **204 No Content** | ✅ Works (CORS OK) |

### 3. Log Analysis
- Server logs confirm requests to `/support/tickets` are reaching the API container and being processed by Fastify.
- No 405 or HTML responses were generated by the API.

### 4. Root Cause Analysis
The reported symptoms match the behavior of a Single Page Application (SPA) server:
- **Symptom 1 (`GET` returns HTML)**: Frontends (SPAs) return `index.html` for unknown routes to handle client-side routing.
- **Symptom 2 (`POST` returns 405)**: Static file servers/Frontend servers typically do not allow `POST` requests, returning "Method Not Allowed".

**Conclusion**: The client configuration is likely pointing to `https://app.manhquy.click` (Frontend) instead of `https://api.manhquy.click` (Backend).

## Recommended Fix

### For the Client/Frontend Team
1. **Verify Base URL**: Check the environment configuration (e.g., `.env`, `config.js`) in the client application.
   - ❌ Incorrect: `NEXT_PUBLIC_API_URL=https://app.manhquy.click`
   - ✅ Correct: `NEXT_PUBLIC_API_URL=https://api.manhquy.click`
2. **Update**: Change the API Base URL to the correct backend endpoint.

### For Operations (Optional)
- Ensure no redirect rules in the load balancer (Caddy) are inadvertently redirecting API traffic to the frontend, though current tests show correct routing.

## Unresolved Questions
- None. API is confirmed healthy.
