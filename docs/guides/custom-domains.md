# Custom Domains Guide

Configure and manage your own custom domains for receiving emails with TempMail Pro. Custom domains provide a professional way to receive emails and better deliverability.

## Overview

Custom domains allow you to:
- Use your own domain names for inboxes
- Improve email deliverability
- Maintain brand consistency
- Better control over email infrastructure
- Set up proper SPF/DKIM/DMARC records

## Prerequisites

- Domain name registered with a DNS provider
- Access to DNS management for your domain
- TempMail Pro instance running

## Step 1: Add Your Domain

1. **Access the Admin Panel**
   - Log in to TempMail Pro
   - Navigate to "Domains" section

2. **Add Domain**
   - Click "Add Domain"
   - Enter your domain name (e.g., `yourcompany.com`)
   - Optionally add a description
   - Click "Save"

## Step 2: Configure DNS Records

### Required Records

You need to configure these DNS records to receive emails:

#### 1. MX Record
Points to TempMail Pro's mail server:

```
Type: MX
Priority: 10
Value: mail.yourdomain.com
```

#### 2. SPF Record
Prevents email spoofing:

```
Type: TXT
Value: v=spf1 mx include:_spf.tempmailpro.com ~all
```

#### 3. DKIM Record
Ensures email integrity (generated by TempMail Pro):

1. Go to Domain → Your Domain → Generate DKIM
2. Copy the DKIM public key
3. Add to DNS:
   ```
   Type: TXT
   Host: mail._domainkey.yourdomain.com
   Value: v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...
   ```

#### 4. DMARC Record
Provides policy for email authentication:

```
Type: TXT
Host: _dmarc.yourdomain.com
Value: v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@yourdomain.com
```

### Optional Records

#### MTA-STS Record
Enforces TLS encryption:

```
Type: TXT
Host: _mta-sts.yourdomain.com
Value: v=STSv1; mode=enforce; max_age=86400
```

#### TLS-RPT Record
Reports TLS issues:

```
Type: TXT
Host: _tlsrpt.yourdomain.com
Value: v=TLSRPTv1; rua=mailto:tls-reports@yourdomain.com
```

## Step 3: Verify Domain Configuration

1. **TempMail Pro Verification**
   - Go to Domain → Your Domain → Verify
   - Click "Verify DNS Configuration"
   - TempMail Pro will check your DNS records

2. **Manual Verification**
   ```bash
   # Check MX records
   dig yourdomain.com MX

   # Check SPF record
   dig yourdomain.com TXT | grep spf

   # Check DKIM record
   dig mail._domainkey.yourdomain.com TXT

   # Check DMARC record
   dig _dmarc.yourdomain.com TXT
   ```

## Step 4: Test Email Reception

1. **Create an Inbox**
   - Go to Inboxes → Create Inbox
   - Select your domain
   - Click "Create"

2. **Send Test Email**
   ```bash
   # Using command line
   python - <<'EOF'
   import smtplib
   from email.message import EmailMessage

   msg = EmailMessage()
   msg['From'] = 'test@yourdomain.com'
   msg['To'] = 'test-inbox@yourdomain.com'
   msg['Subject'] = 'Test Email'
   msg.set_content('This is a test to verify your domain configuration.')

   with smtplib.SMTP('localhost', 2525) as server:
       server.send_message(msg)
       print("Test email sent!")
   EOF
   ```

## Advanced Configuration

### Multiple Domains

You can add multiple domains:
```bash
# Add multiple domains via API
curl -X POST "http://localhost:3001/domains" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "domain1.com",
    "description": "Primary domain"
  }'

curl -X POST "http://localhost:3001/domains" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "domain2.com",
    "description": "Secondary domain"
  }'
```

### Domain Aliases

Set up domain aliases (requires DNS configuration):
```
# Add CNAME record
Type: CNAME
Host: alias.yourdomain.com
Value: yourdomain.com
```

### Subdomain Support

Use subdomains for better organization:
```
# Create DNS records for subdomain
mail.sub.yourdomain.com IN A 192.168.1.100
```

## DNS Provider Examples

### Cloudflare

1. **Login to Cloudflare**
2. **Select your domain**
3. **Add DNS Records**:
   - MX: `mail.yourdomain.com` priority 10
   - TXT: SPF record
   - TXT: DKIM record
   - TXT: DMARC record
4. **Proxy Status**: Use DNS only (orange cloud) for mail records

### GoDaddy

1. **Login to GoDaddy**
2. **Domains → Manage**
3. **DNS Management**
4. **Add Records**:
   - MX: `@` `mail.yourdomain.com` priority 10
   - TXT: SPF, DKIM, DMARC records
5. **Save changes**

### Google Domains

1. **Login to Google Domains**
2. **Select domain**
3. **DNS → Configure DNS**
4. **Add Records**:
   - Custom MX: `mail.yourdomain.com` priority 10
   - TXT records for SPF, DKIM, DMARC
5. **Save**

## Troubleshooting

### Common Issues

**DNS Propagation Delay**
- DNS changes can take 24-48 hours to propagate
- Use `dig` or `nslookup` to check propagation
- Use online DNS checkers

**Email Bouncing**
- Check SPF alignment
- Verify DKIM record is correct
- Ensure DMARC policy is not set to `reject`

**Port 25 Blocked**
- Some ISPs block port 25
- Use port 587 (submission) with authentication
- Contact your ISP for port 25 unblocking

### Debug Commands

```bash
# Check DNS records
dig yourdomain.com ANY

# Test SMTP connection
telnet yourdomain.com 25

# Check SPF record
spfquery -m envelope-from@test.com -h yourdomain.com

# Test DKIM alignment
opendkim-testkey -d yourdomain.com -s mail

# Verify DMARC record
dmarc-analyzer yourdomain.com
```

## Security Considerations

### SPF Best Practices

```
v=spf1
mx                 # Include your own MX
include:_spf.tempmailpro.com  # Include TempMail Pro
-all               # Fail if not matched
```

### DKIM Best Practices

- Use 2048-bit RSA keys
- Rotate keys every 6-12 months
- Monitor key strength regularly

### DMARC Best Practices

```
v=DMARC1;
p=quarantine;      # or p=reject for strict policy
 rua=mailto:dmarc-reports@yourdomain.com;
 ruf=mailto:forensic-reports@yourdomain.com;
 pct=100;
 sp=none;
 adkim=s;
 aspf=s;
```

## API Examples

### Domain Management

```javascript
// Add domain
const domain = await fetch('/domains', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`,

// Verify domain

```
